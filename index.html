Supabase を
直接つないで測ってみよう

前回は、ブラウザ → GAS → Supabase という「中継ぎ」を通して測りました。今回は中継ぎ（GAS）を通さず、ブラウザから Supabase に直接つないで、かかった時間を測ります。

何を確かめるの？

GAS経由の結果には、データベース本体の時間のほかに、GASが間に入る時間も含まれています。荷物を届けるときに、直接届けるか、中継所を通すかの違いです。

直通で測ると、中継ぎの分がなくなります。GAS経由との差が、そのまま「GASを通すのにかかった時間」の目安になります。

遊び方

  1. 各実験で「5回連続で測定」を押すと、同じ操作を5回続けて実行し、平均を出します。
  2. 「1回だけ」を押すと1回分が追加されます。何回でも積み上がり、平均は自動で更新されます。
  3. 表示された時間（ミリ秒）を見ます。数字が小さいほど速いです。1000ミリ秒 = 1秒です。
  4. 一番下の「平均値の比較」で、直通とGAS経由の差を文章で確認できます。
※ 同じ操作でも毎回数百ミリ秒ほどぶれます。だから5回の平均を使います。エラーになった回は平均から除外し、エラー回数として別に数えます。

用語メモ

直通とGAS経由は何が違うの？

GAS経由は「ブラウザ → GAS → Supabase」と2回の通信が必要です。直通は「ブラウザ → Supabase」の1回だけです。そのぶん直通のほうが、通常は数百ミリ秒ほど速くなります。

ミリ秒（ms）とは？

1000分の1秒です。「800ms」は約0.8秒です。

エラーになるのはなぜ？

実験2は約100万件を全部見るため重く、Supabaseが決めた制限時間（標準で約3秒）を超えると、途中で強制終了されます。これを「タイムアウト」と呼びます。エラーの理由は、測定結果の下に表示されます。

JOIN（ジョイン）とは？

別々の表を、共通の項目（今回は社員のID）でつなげて1つの表のように扱うことです。

なぜ5回測って平均を出すの？

通信の混み具合などで、1回ごとの時間は大きくぶれます。数回測って平均を見ると、全体の傾向がつかみやすくなります。
